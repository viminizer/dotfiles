# dotfiles

This repo **is** `~/.config`. It is cloned there, not symlinked into it — most
tools read `~/.config/<tool>` directly, so putting the checkout in the right
place is most of the install. `install.sh` covers the rest and is safe to re-run.

The one exception is zsh, which only ever reads `~/.zshrc`; `install.sh` links
that at the tracked copy.

## Branches

| Branch | Holds |
| --- | --- |
| `master` | Everything that is true on every machine |
| `<hostname>` (e.g. `kevins-macbook-pro`) | Only what genuinely differs per machine |
| `theme/*` | Theme variants, generated by `theme/apply.py` |

Machine branches are rebased onto `master`, not merged. A change belongs on
`master` unless it would be *wrong* on another machine — "I happen to like it
here" is not machine-specific. When in doubt, put it on `master`.

Before committing to a machine branch, ask whether the change is coupled to
this display, this keyboard, or this set of installed apps. Most are not.

## Screen geometry (the part that keeps biting)

AeroSpace lays windows out inside `NSScreen.visibleFrame`, **not** the physical
frame. On a notched Mac macOS shrinks that by the 32pt safe area, and keeps
shrinking it whether or not the menu bar is hidden. So `gaps.outer.top` is not
"distance from the top of the screen" — it is distance from an origin that has
already been moved down on some machines and not others. That is why it lives on
machine branches.

To measure a machine rather than guess:

```swift
import AppKit
let s = NSScreen.main!
print(s.frame, s.visibleFrame, s.safeAreaInsets.top)
```

`outer.top` = (sketchybar `y_offset` + `height`) − `safeAreaInsets.top`, plus a
couple of px so the `bordersrc` window border does not touch the bar's border.

## sketchybar

The bar's `height` is load-bearing. Item and bracket `background.height` values
are sized against it, so changing one without the others leaves pills swimming
in the bar or clipped by it. The current ratios:

| | height | margin inside bar |
| --- | --- | --- |
| bar | 34 | — |
| item pills | 26 | 4px |
| workspaces bracket | 30 | 2px |
| status bracket | 28 | 3px |
| `cpu_graph` | 22 | sits inside the 28px status bracket |

Graphs are scaled 0..1 by whatever pushes to them. `plugins/cpu.sh` pushes
`sqrt(c/100)` rather than `c/100`: linear is honest but unreadable, because the
machine idles at 1–9% and that is under 2px of a 22px pill. The label always
carries the true number, so nothing is misreported.

Items are driven by `update_freq` plus scripts in `plugins/`. To test one
without waiting for the timer:

```sh
NAME=cpu sh sketchybar/plugins/cpu.sh
sketchybar --query cpu_graph
```

`sketchybar` and `borders` run under launchd (`brew services`), not as children
of AeroSpace, so they come back on their own after a crash. Restart with
`brew services restart sketchybar` — a plain `--reload` will not pick up bar
geometry changes.

## Themes

`theme/apply.py` repaints kitty, tmux, sketchybar and borders from a single
kitty theme. It works by **role**, not by literal colour: `theme/current.json`
records which hex is currently playing `bg`, `accent`, `alert` and so on, and
repainting substitutes role by role. That is what keeps hand edits to the
configs intact.

The practical consequence: a hardcoded colour added to one of those four configs
will be silently rewritten on the next theme apply. Add it as a role instead.

## Packages

`Brewfile` holds only what the tracked configs reference — every entry is
reachable from a config file, so dropping one breaks something visible.
Everything else this machine happens to have is in `Brewfile.extras`, which
`install.sh` deliberately does **not** install.

Casks that ship a `.pkg` (`temurin@21`, `karabiner-elements`, `font-sf-pro`)
shell out to `sudo` and cannot be installed from a non-interactive shell. They
need a real terminal.

## Not tracked, and why

- **Fonts.** `Osaka`/`Osaka-Mono` are Apple's, shipped as an on-demand asset
  under AssetsV2 rather than an installed font — copy them to `~/Library/Fonts`
  by hand. The rest come from casks in the `Brewfile`.
- **tmux plugins.** Managed by tpm; `prefix + I` after first launch.
- **Anything under the ignore list** in `.gitignore` — credentials and tool
  state, which is the reason the list exists rather than a `*` allowlist.

## House style

Config comments explain *why*, not what — they are there for the next person who
wonders why a value is odd, and several encode a measurement or a bug that was
hit once. Match that when editing: a bare number with no reason attached is the
thing this repo is trying not to have.
