The teaching setup, and how to drive it

Your daily editor stays exactly as fast and quiet as it was. Everything built here sits behind one toggle and a <leader>t group, so nothing new fires until a lesson starts.

4 new files · 4 edited · 11 keymaps · 3 plugins · verified against a live vtsls session
the one thing to remember

<leader>tt turns the classroom on. Press it again to get your editor back. Everything else in this page is either something that toggle flips for you, or a tool you reach for during the lesson itself.

01

Why a toggle instead of a new config

A teaching editor and a working editor want opposite things. Teaching wants inlay hints everywhere, big type, absolute line numbers, and a slow readable pace. Working wants none of that in the way.

Keeping two configs means keeping two configs in sync forever. So instead: one config, and a single function that flips the handful of settings that actually differ, then puts them all back.

default state

Everything teaching-related is off. No inlay hints, no codelens, no keystroke overlay. Startup cost is unchanged.

teach mode

One keypress flips eight things at once, including your kitty font size, and puts a TEACH marker in lualine so you never confuse it for normal.

always on

The vtsls settings that only make output better when asked stay on permanently. They cost nothing until something requests them.

02

Teach mode

<leader>tt

One toggle, eight changes. Press it before you start recording and again when you are done.

WhatNormallyIn teach modeWhy it matters in front of people
Inlay hints off on Inferred types drawn inline. The difference between "trust me, it's a string" and showing it.
Codelens off on "1 reference" above each function, and who implements each interface.
checkJs + strict off on Plain .js files with no tsconfig get type-checked, so you can show real type errors before TypeScript enters the course.
Line numbers relative absolute Relative numbers are great for you and useless to a student. "Look at line 42" has to mean line 42.
Cursor thin underline blinking block An underline cursor disappears once the video is scaled down to a laptop window.
Diagnostic float opens on hover pause off Teaching means pausing to talk, and every pause fires CursorHold. It would spend the lesson covering the line you are explaining.
kitty font 16pt 21pt Sent over kitty's remote-control socket. Turning teach mode off sends set-font-size 0, which restores whatever kitty.conf says rather than hardcoding 16 in a second place.
Keystroke overlay off top-right Answers "what did you just press" without you narrating every motion.

While it is on, lualine carries a red TEACH marker and, in a course repo, the beat you are currently sitting on.

one gotcha worth knowing

The checkJs and strict flags are pushed to vtsls at runtime, not baked into your config. That is on purpose: they apply to every .js file that is not part of a tsconfig project, so leaving them on permanently would light up unrelated config files and one-off scripts with errors nobody asked for.

03

Types on screen

always on

These vtsls settings are permanent. None of them draw anything on their own; they only make the answer better when something asks. That is why they can stay on during normal work.

What was actually holding you back

LazyVim's TypeScript extra already enabled most inlay hints. Two things kept them from being useful:

variableTypes was off

This is the hint that draws const grand: number. It was the one thing the extra disabled, and it is the entire point when the subject is types. Now on.

everything was truncated

Hints cut off at 30 characters and hover at 500. The types worth putting on a projector are exactly the long ones. Now 80 and 3000.

Verified on a real file

Seven lines of TypeScript, run against a live vtsls session. Ten hints came back:

// what vtsls now returns for a 7-line file export function total(items: { price: number; qty: number }[]) { → : number return items.reduce((sum, item) => ..., 0); → callbackfn: initialValue: : number } const cart = [{ price: 3, qty: 2 }]; → : { price: number; qty: number }[] const grand = total(cart); → : number items: // and above line 0, a codelens: 1 reference

The rest of it

All of it applies to JavaScript too. LazyVim's extra copies the typescript.* block over to javascript.*, so one set of settings covers both halves of the course.

04

Twoslash queries

<leader>tq

Hover works, but it vanishes the moment the cursor moves. A twoslash query is a type that stays on screen while you talk about it — and it is the same // ^? syntax the TypeScript handbook uses, so students can copy the pattern into their own editor.

1Press <leader>tq to arm it for the session.
→
2Write // ^? with the caret under the thing you care about.
→
3The type renders inline, multi-line, and stays there.
→
4<leader>tQ when you want a clean screen again.
const cart = [{ price: 3, qty: 2 }]; const grand = total(cart); // ^? // const grand: number

It starts disarmed on purpose. Otherwise every stray ^? in a comment starts rendering types mid-lesson. <leader>ti inspects whatever is under the cursor without writing a query at all.

05

Readable TypeScript errors

automatic

Nothing to press. ts-error-translator rewrites vtsls diagnostics into plain English before they reach you, in every JS and TS buffer.

what TypeScript says

Type 'string' is not assignable to type 'number'.

what you read out

A plain-language explanation of which value is wrong and what was expected instead.

Worth it for two reasons: reading a raw TypeScript error aloud is not teaching, and every student in the room is also parsing it as a second language.

06

Course beats

turnout · shortlist · pulse

In those repos the git history is the product: one commit and one tag per beat, numbered 1, 1.1, 1.1.1. Teaching means checking out a beat, talking about it, moving on. turnout alone has 129 tags — more than anyone remembers, and git checkout means leaving the editor mid-lesson.

during a lesson

<leader>tn and <leader>tp walk forward and back one beat. No picker, no typing, no breaking flow.

jumping anywhere

<leader>tb opens all beats, each labelled with its commit subject, so you pick by what it teaches rather than by number.

-- what the picker shows 1.1.1 express in five lines 1.1.2 the web-basics routes, rewritten 1.1.3 route params and query strings 1.1.4 ...

<leader>td diffs the current beat against the one before it, in a new tab, so the class sees exactly what this step introduced and nothing else.

it will refuse to move on a dirty worktree

Every checkout checks git status first and stops with a warning if anything is uncommitted. Losing live edits in front of a class is not a recoverable mistake. Buffers also reload from disk automatically after a jump, so the screen never shows the previous beat while the files have already moved on.

07

Running code without leaving the editor

<leader>tr

<leader>tr in normal mode runs the whole buffer. In visual mode it runs just the selection, which is how you show one idea at a time. Output lands in a tmux pane below the editor.

paneOpened once, 30% height, reused after that. Never stacks up.
→
bunRuns .ts directly. No build step, no config, no waiting. Falls back to node.
→
temp fileCode is written to a file first, never pasted into the shell.
→
clearEach run clears first, so the pane only ever shows this result.

The temp-file step matters more than it looks: pasting a multi-line snippet straight into a shell gets mangled by bracketed paste and pollutes your shell history with lesson code. <leader>tR closes the pane when you are done.

Every key

11 new · no collisions

<leader>t is a group of its own. LazyVim had already claimed most of <leader>u and <leader>c, and nothing else on your setup owned <leader>t.

KeyDoesWhen you reach for it
<leader>ttTeach mode toggleBefore you hit record. And again after.
<leader>tkKeystrokes toggleStandalone, if you want the overlay without the rest of teach mode.
<leader>tbBeat pickerJumping to a specific lesson by name.
<leader>tnNext beatMid-lesson, moving forward one step.
<leader>tpPrevious beatBacking up to re-explain something.
<leader>tdDiff vs previous beat"Here is exactly what changed in this step."
<leader>trRun buffer / selectionNormal mode runs the file, visual mode runs the selection.
<leader>tRClose runner paneReclaiming the screen.
<leader>tqTwoslash enableBefore a segment built around types.
<leader>tQTwoslash disableClean screen again.
<leader>tiTwoslash inspectOne-off type under the cursor, no comment needed.

Still worth knowing

  • <leader>uh — inlay hints alone, LazyVim's own toggle. Use this when you want hints for a moment without the whole teaching setup.
  • K — hover, now with the 3000-character limit.
  • gD — go to source definition, now landing in real source instead of a .d.ts.
  • gR — file references. Already existed, unchanged.

10

Left to you

not touched, as you asked

background_opacity 0.7 and background_blur 10 in kitty.conf are exactly as they were.

Worth knowing when you do get to it: at 0.7 your desktop shows through the code. On a recording or a projector that costs real contrast, and it is the single biggest legibility problem left. Your transparent nightfox setup does the same thing from the other direction.

When you want it, teach mode is the natural place to put it — one more line that goes opaque on, back to 0.7 off, the same way the font size already works.

Two things to try before the first real lesson

  • Turn teach mode on and watch it back at laptop size. That is where 21pt either works or does not, and it is a one-line change either way.
  • Walk three beats of turnout with <leader>tn while teach mode is on, so you find out whether the beat indicator and the codelens together are helpful or just busy.
